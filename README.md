# بک‌اند پروژه آشپزخانه
# کارگروه برنامه‌نویسی

## اجرای پروژه

```bash
python -m venv .venv
.venv\Scripts\activate
pip install django
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8090
```

کاربر نمونه برای ورود: کد ملی `0012345678` و رمز عبور `ashpazkhane`.

## پنل مدیریت

حساب مدیر با دستور زیر ساخته یا به‌روزرسانی می‌شود:

```bash
python manage.py create_admin
```

مقادیر پیش‌فرض: کد ملی `0000000000` و رمز عبور `admin12345`. **این رمز فقط برای محیط توسعه است؛ در محیط واقعی با `--password` یک رمز قوی بگذارید.** برای تغییر:

```bash
python manage.py create_admin --code 1234567890 --password MyPassword --first-name مدیر --last-name آشپزخانه
```

پس از ورود با همین کد ملی، مدیر به‌طور خودکار وارد `/panel/` می‌شود و صفحه‌های کاربر عادی (منو، سبد خرید و خریدهای من) برای او نمایش داده نمی‌شود. از مسیر `/panel/` می‌توانید:

- **داشبورد:** تعداد افراد و وعده‌های امروز، این هفته، این ماه و کل.
- **سفارش‌ها:** مشاهدهٔ خریدها بر اساس روز، هفته یا ماه، جست‌وجوی دانش‌آموز با نام یا کد ملی، دیدن افراد هر روز و **خروجی اکسل** از همان فیلتر.
- **لیست تحویل روز:** وقتی یک روز را انتخاب کنید، دکمهٔ «لیست تحویل روز (اکسل)» فقط نام و کد ملی همان روز را برای چاپ می‌دهد.
- **گزارش مالی:** درآمد هر ماه، مقایسه با ماه قبل، تعداد وعده‌ها و میزان پرشدن ظرفیت.
- **پرداخت‌ها:** تاریخچهٔ همهٔ تلاش‌های پرداخت (موفق و ناموفق) و بررسی دستی سفارش‌های در انتظار پرداخت.
- **کاربران:** ساخت کاربر، جست‌وجو، **تغییر رمز عبور** و **فعال/غیرفعال‌کردن** حساب.
- **منوی ماه:** ساخت ماه جدید و وارد کردن نام غذا، قیمت و **ظرفیت روزانه** هر روز.

پنجشنبه و جمعه آشپزخانه تعطیل است؛ این روزها در منو نمایش داده می‌شوند ولی قابل خرید نیستند و در پنل هم برای آن‌ها غذا ثبت نمی‌شود.

## مهلت سفارش و ظرفیت

- مهلت خرید هر وعده **ساعت ۹ صبح همان روز** است. مثلاً اگر جمعه باشد، غذای شنبه را می‌توان تا ساعت ۹ صبح شنبه خرید و بعد از آن آن روز بسته می‌شود.
- «افزودن کل ماه» روزهای بسته و پر را نادیده می‌گیرد.
- آیتم‌هایی که مهلتشان در سبد خرید تمام شده، هنگام دیدن سبد یا پرداخت خودکار حذف می‌شوند.
- اگر برای یک روز ظرفیت تعیین شود (مثلاً ۵۰ غذا)، بعد از رسیدن به این تعداد دکمهٔ خرید غیرفعال و برچسب «ظرفیت تکمیل» نمایش داده می‌شود. ظرفیت `0` یعنی بدون محدودیت.
- ساعت مهلت با متغیر `ORDER_CUTOFF_HOUR` در فایل `.env` قابل تغییر است.

## نصب روی گوشی (PWA)

سایت یک مانیفست و سرویس‌ورکر دارد. در مرورگر گوشی، از منوی مرورگر «افزودن به صفحهٔ اصلی» را بزنید تا مثل یک برنامه باز شود. برای فعال‌شدن کامل PWA، سایت باید روی HTTPS اجرا شود (یا localhost).

## تنظیمات محرمانه (`.env`)

مقدارهای حساس از فایل `.env` در کنار `manage.py` خوانده می‌شوند. فایل نمونه:

```bash
copy .env.example .env
```

| متغیر | توضیح |
| --- | --- |
| `DJANGO_SECRET_KEY` | کلید امنیتی جنگو؛ در محیط واقعی حتماً عوض شود |
| `DJANGO_DEBUG` | `0` در محیط واقعی |
| `DJANGO_ALLOWED_HOSTS` | دامنه‌ها با کاما، مثل `example.com,www.example.com` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | آدرس کامل HTTPS سایت (اختیاری) |
| `DJANGO_DB_PATH` | مسیر فایل دیتابیس (اختیاری) |
| `ZARINPAL_SANDBOX` | `1` آزمایشی، `0` واقعی |
| `ZARINPAL_MERCHANT_ID` | شناسهٔ پذیرنده |
| `ZARINPAL_BASE_URL` | آدرس پایهٔ درگاه (اختیاری) |
| `ORDER_CUTOFF_HOUR` | ساعت پایان سفارش هر روز (پیش‌فرض ۹) |
| `CLOCK_OFFSET_MINUTES` | اصلاح اختلاف ساعت سیستم به دقیقه؛ روی سرور درست `0` بماند |
| `LOGIN_MAX_ATTEMPTS` | تعداد تلاش ناموفق ورود پیش از قفل موقت (پیش‌فرض ۶) |
| `LOGIN_LOCKOUT_SECONDS` | مدت قفل موقت ورود به ثانیه (پیش‌فرض ۶۰۰) |
| `DJANGO_SECURE_COOKIES` | ارسال کوکی‌ها فقط روی HTTPS (در حالت واقعی پیش‌فرض `1`) |
| `DJANGO_SECURE_SSL_REDIRECT` | هدایت خودکار HTTP به HTTPS (اختیاری) |
| `DJANGO_HSTS_SECONDS` | فعال‌سازی HSTS؛ مثلاً `31536000` |
| `DJANGO_TRUST_PROXY_SSL` | اگر پشت پراکسی HTTPS هستید `1` بگذارید |

> فایل `.env` محرمانه است و در `.gitignore` قرار گرفته؛ آن را در گیت یا پیام‌رسان منتشر نکنید.

## خرید و پرداخت

- هر کاربر برای خرید باید وارد حساب خود شود؛ افزودن به سبد و پرداخت در سمت سرور بررسی می‌شود.
- کاربر می‌تواند روزهای موردنظر یا کل یک ماه را به سبد خرید اضافه کند و همه را با هم پرداخت کند.
- هر کاربر یک سفارش «در انتظار پرداخت» (سبد خرید) و چند سفارش «پرداخت‌شده» (تاریخچه) دارد.
- مبلغ‌ها در پایگاه داده به تومان ذخیره می‌شوند و هنگام ارسال به زرین‌پال در ۱۰ ضرب می‌شوند (ریال).

### تنظیم درگاه زرین‌پال

به‌طور پیش‌فرض درگاه در حالت آزمایشی (Sandbox) اجرا می‌شود. برای تغییر، متغیرهای `ZARINPAL_*` را در فایل `.env` تنظیم کنید (جدول بالا).

## نکات امنیتی پیاده‌شده

- ورود با محدودیت تلاش (پیش‌فرض ۶ بار در ۱۰ دقیقه) و پیام یکسان برای جلوگیری از حدس رمز.
- بازگشت پس از ورود فقط به آدرس‌های داخلی سایت (جلوگیری از Open Redirect).
- همهٔ صفحه‌های خرید و سبد با `login_required` محافظت می‌شوند و مالکیت هر آیتم در سرور بررسی می‌شود.
- پنل فقط برای `is_staff`؛ مدیریت پیشرفتهٔ جنگو (`/admin/`) فقط برای `is_superuser`.
- ساخت حساب مدیر و تغییر حساب مدیران دیگر فقط توسط مدیر ارشد.
- رمز عبور حداقل ۸ نویسه، غیرعددی و متفاوت از کد ملی؛ برای مدیران اعتبارسنجی کامل جنگو.
- اعتبارسنجی دوبارهٔ مهلت، ظرفیت و تکراری‌بودن سبد پیش از انتقال به درگاه، با تراکنش و قفل ردیف‌ها.
- تأیید مبلغ و کد پرداخت در سرور؛ پذیرش کد پرداخت تلاش‌های قبلی همان سفارش؛ جلوگیری از پردازش دوبارهٔ سفارش پرداخت‌شده.
- خروج خودکار حساب‌هایی که پس از ورود غیرفعال شده‌اند.
- جلوگیری از تزریق فرمول اکسل در خروجی‌ها.
- هدرهای امنیتی، کوکی‌های HttpOnly/SameSite و تنظیمات HTTPS برای محیط واقعی.
- خطای واضح در شروع برنامه اگر در حالت واقعی `SECRET_KEY` یا `ZARINPAL_MERCHANT_ID` پیش‌فرض باقی مانده باشد.

## آزمون‌ها

```bash
python manage.py test Menu
```

آزمون‌ها شامل جلوگیری از خرید بدون ورود، افزودن یک روز، افزودن کل ماه، جلوگیری از خرید تکراری، انتقال به درگاه و تأیید پرداخت (با شبیه‌سازی پاسخ زرین‌پال)، مهلت ساعت ۹ صبح، ظرفیت روزانه، گزارش مالی، لیست تحویل روز، ثبت تلاش پرداخت و مدیریت کاربران است.
